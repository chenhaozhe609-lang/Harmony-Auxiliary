## A1：建立工作区、基础设施和可观测性骨架

| ID | 任务 | 交付物 | 完成标准 |
| --- | --- | --- | --- |
| ARC-01.1 | 重划仓库边界 | `apps/web`、`apps/api`、`packages/domain`、`packages/contracts`、`packages/harmony-core`、`infra` 的工作区配置 | Web、API、领域类型和算法可独立构建；不产生循环依赖 |
| ARC-01.2 | 建立环境与密钥边界 | 本地/预发布/生产环境清单、示例变量和受控密钥说明 | 客户端只含可公开配置；数据库、存储和服务凭据不进入源码或浏览器包 |
| ARC-01.3 | 建立数据库迁移与新库初始化 | 可重复执行的迁移、空库初始化说明 | 从空数据库能构建所需 schema；迁移在 CI 中验证；不含旧测试数据导入 |
| ARC-01.4 | 建立 API 健康与版本标识 | `/health`、`/ready`、发布版本标记 | 能区分进程存活、依赖就绪和发布版本；部署探针可用 |
| ARC-01.5 | 建立 CI 质量门 | CI 流水线 | 类型检查、单元测试、契约测试、迁移测试、关键浏览器回归和依赖安全检查均有明确失败门槛 |
| ARC-01.6 | 建立日志、指标和告警基础 | 结构化日志字段、仪表盘和告警规则 | 请求 ID、发布版本、错误类别可关联；核心 API/同步/音频指标可被采集 |

**A1 退出门槛：** 从全新环境可构建、迁移、启动并观测最小 Web/API 系统。

## A2：本地优先项目库与版本化 API

| ID | 任务 | 交付物 | 完成标准 |
| --- | --- | --- | --- |
| ARC-02.1 | 定义共享领域与 API 契约 | `Project`、`ProjectRevision`、`ProjectChange`、冲突、认证、错误码契约 | Web/API/算法对同一字段、版本号和错误含义达成一致；有契约测试 |
| ARC-02.2 | 设计 PostgreSQL schema 与索引 | 用户、项目、修订、变更记录 schema | 项目所有权与修订不可变；查询不依赖 JSON 全表扫描；可追溯变更来源 |
| ARC-02.3 | 建立多项目 IndexedDB 仓库 | 本地项目索引、内容、待同步队列、迁移策略 | 断网可创建/切换多个项目，重启后保留；不只保存单一 active 快照 |
| ARC-02.4 | 实现版本化项目 API | 鉴权、读取、创建、提交修订、拉取变更接口 | 所有项目访问经过服务端授权；写入携带基线版本并返回明确冲突 |
| ARC-02.5 | 实现幂等同步与冲突呈现 | 客户端同步状态机、幂等键和冲突 UI 契约 | 重试不生成重复修订；网络恢复可同步；冲突不静默覆盖且可恢复本地副本 |
| ARC-02.6 | 建立本地模式与账户升级路径 | 离线状态、登录后归属/合并流程 | 未登录或服务不可用时仍能创作；登录后用户可主动决定同步/归属 |

**A2 退出门槛：** 断网编辑、重启、恢复联网、并发编辑冲突四种流程均有自动化或可复现集成测试。

## A3：音频资源层与性能治理

| ID | 任务 | 交付物 | 完成标准 |
| --- | --- | --- | --- |
| ARC-03.1 | 定义音频分层接口 | 本地合成 fallback、采样增强、资源状态的统一接口 | 试听调用不关心来源；任何增强资源失败自动回落本地合成 |
| ARC-03.2 | 建立受控资产清单 | 音频许可证、来源、版本、音区、大小、哈希清单 | 不再把匿名第三方 CDN 作为生产关键依赖；资产可追溯并可替换 |
| ARC-03.3 | 实现零网络首播 | 默认合成音色和首次交互路径 | 冷缓存、离线、采样下载失败时，首次点击可立即发声且不等待网络 |
| ARC-03.4 | 实现渐进采样、预取和缓存 | 采样加载器、Cache Storage 策略、音区预取规则 | 已缓存资源离线可复用；切换音色不重复创建竞争 sampler；缓存失败不破坏 fallback |
| ARC-03.5 | 建立音频性能指标 | 首次可听时间、失败率、缓存命中率、下载字节、切换耗时指标 | 指标带发布版本/设备或网络维度；有告警或至少可查询仪表盘 |

**A3 退出门槛：** 冷缓存在线、离线、采样服务失败三种场景均完成首播与降级验证。

## A4：前端依赖切换

| ID | 任务 | 交付物 | 完成标准 |
| --- | --- | --- | --- |
| ARC-04.1 | 替换 Supabase client/repository | 自有项目仓库与 API client | 前端不再直连 Supabase 表；不再以 VITE Supabase 配置判断整体工作台是否可用 |

| ARC-04.3 | 接入新音频层 | 统一 audio service 调用点 | 播放、预览、候选试听与导出互不阻塞；资源状态可呈现 |
| ARC-04.4 | 移除遗留运行时依赖 | 删除或隔离旧 Supabase 路径、无效 env 和第三方样本 URL | 生产包、代码搜索和运行时网络请求均无旧核心依赖 |

**A4 退出门槛：** 从浏览器网络面板和打包结果可证明核心创作流不触达旧 Supabase/第三方样本 CDN。
