# Task 4: Realistic Playback Tone and FL Studio Piano Roll

## 1. 背景

本轮反馈来自继续试用。Task 3 已经解决了播放暂停、从头/从当前小节播放、纵向拖动改音高、工作台控制收纳和落地页简化，但试用者认为离“真正像音乐工具”还差三件事：

- 播放器音色不够好听，合成器味道太重，听起来不像真实乐器。
- 旋律编辑区每个八度只显示了部分白键（C4–C5 共 8 行），需要扩展为标准的“一个八度 12 个半音”，并覆盖约 3 个八度；同时旋律窗口和和声窗口挤在同一个滚动容器里，应拆成两个对齐但各自可滑动的窗口。
- 手动输入还不够像 FL Studio 的钢琴卷帘：缺少左侧真正的黑白琴键、缺少足够音域、点击与拖动的卷帘体验不够直觉。

Task 4 的目标不是把产品做成完整 DAW 或采样器音源平台，而是把“音色”和“输入卷帘”这两项体验拉到接近真实音乐工具的水平。

## 2. 产品目标

1. 默认播放音色升级为采样真实乐器（钢琴），明显减少合成器感。
2. 旋律卷帘的音高行从“部分白键”升级为“标准 12 半音 / 八度”，并覆盖约 3 个八度的音域。
3. 旋律窗口与和声窗口拆分为两个独立可纵向滚动的窗口，但横向节奏网格严格对齐、横向滚动联动。
4. 手动输入区参照 FL Studio：左侧固定黑白琴键、卷帘内点击建音、拖动改时间/音高、边缘拖动改时值。

## 3. 非目标

本轮暂不做以下内容：

- 完整 DAW 多轨录音、自动化包络、混音台。
- 多采样力度层、踏板共鸣、真实采样器音源管理界面。
- 用户上传自定义音源或自定义采样映射。
- 黑白键真实物理宽度比例与琴键 3D 拟物。
- MusicXML 导入导出、撤销栈系统重构。

## 4. 任务拆分

### T4.1 采样真实乐器音色

目标：默认播放不再是明显的合成器音色，而是采样钢琴。

任务：

- 在 `AudioEngine` 中引入基于 `Tone.Sampler` 的采样乐器（钢琴）作为旋律与和声主音色。
- 采样资源按需加载（首屏不阻塞），加载完成前与失败时回退到现有合成器预设，保证离线仍可发声。
- 为采样音色加入轻度空间感（reverb），但不破坏暂停可取消、从指定 beat 起播、melody/harmony mute 行为。
- 默认 `playbackTone` 切换为采样钢琴；保留原合成器预设作为可选项。
- 加载状态在 UI 上有可见反馈（例如“正在加载音色”），不让用户以为播放卡死。

验收标准：

- 默认播放音色明显比当前合成器更接近真实钢琴。
- 采样未加载完成时点击播放不报错，会回退发声或提示加载中。
- 暂停、从头播放、从当前小节播放、mute 行为全部保持正确。
- 采样加载失败（离线）时仍能用回退音色播放。

### T4.2 半音音高行与 3 八度音域

目标：旋律卷帘的音高行符合“一个八度 12 个半音”，并覆盖约 3 个八度。

任务：

- 将 `PITCH_ROWS` 从 8 行白键扩展为约 3 个八度的半音行（例如 C3–B5，36 行）。
- 区分黑键/白键的视觉（行底色或琴键颜色）。
- 点击建音、纵向拖动改音高、note grid row 映射全部基于新的半音行。
- 默认视图滚动到旋律实际音域附近，避免一打开全是空行。

验收标准：

- 每个八度显示 12 个半音行，黑白键可区分。
- 卷帘覆盖约 3 个八度，可纵向滚动查看全部音域。
- 新建/拖动的音符落在正确的半音行，音名与行一致。

### T4.3 旋律与和声拆分为对齐的独立窗口

目标：旋律窗口和和声窗口不再共用一个滚动容器，而是两个对齐但各自可滑动的窗口。

任务：

- 将当前单一 `timeline-grid` 拆分为“旋律窗口”和“和声窗口”两个区域。
- 两个窗口使用同一套 beat→列映射，横向网格严格对齐。
- 旋律窗口可纵向滚动（覆盖 3 八度）；和声窗口保留声部行与和弦标签。
- 横向滚动联动：滚动任一窗口，另一窗口横向同步，保证同一 beat 垂直对齐。
- 小节尺/播放头与两个窗口的横向位置一致。

验收标准：

- 旋律窗口与和声窗口为可见的两个独立窗口。
- 同一 beat 在两个窗口中横向位置对齐。
- 旋律窗口纵向滚动不影响和声窗口。
- 横向滚动其一，另一窗口同步，不发生错位。
- 页面无横向整体溢出。

### T4.4 FL Studio 风格钢琴卷帘输入

目标：手动输入更像 FL Studio 钢琴卷帘。

任务：

- 旋律窗口左侧固定一列黑白琴键（带音名），横向滚动时 sticky。
- 卷帘行 hover 高亮当前音高行。
- 点击卷帘空格在对应 pitch row + beat 建音。
- 拖动音符：横向改 `startBeat`，纵向在半音行间改 `midi/pitchClass/name`。
- 拖动音符右边缘改 `durationBeats`，不改音高。
- 拖动/建音吸附到当前节奏细分格。
- 拖动后清空旧 harmony candidates，避免和声与新旋律不一致（沿用现有逻辑）。
- 可选：点击左侧琴键试听该音高。

验收标准：

- 左侧琴键黑白可分、与卷帘行垂直对齐、横向滚动保持可见。
- 卷帘内点击能在正确音高与节奏位置建音。
- 纵向拖动跨半音行正确改音高并显示新音名。
- 边缘拖动只改时值。
- 生成和声使用拖动后的真实 pitch 与 startBeat。

### T4.5 回归测试与浏览器验证

目标：避免音频、卷帘音域和窗口拆分再次回归。

任务：

- 更新 piano roll 拖动测试以覆盖半音行映射。
- 增加 `AudioEngine` 采样回退选择逻辑测试。
- 增加横向滚动联动 / 网格对齐的浏览器验证。
- 增加半音卷帘建音与纵向拖动改音高的浏览器验证。
- 保留 Task 2/3 已有验证脚本。

验收标准：

- `tsc -b` 通过。
- `vitest run --passWithNoTests` 通过。
- `vite build` 通过。
- 浏览器验证覆盖：
  - 采样音色默认播放（或加载中提示）。
  - 半音卷帘建音与纵向拖动改音高。
  - 旋律/和声两个窗口横向对齐且滚动联动。
  - 工作台与卷帘无横向溢出。

## 5. 建议实施顺序

1. T4.1 采样真实乐器音色。
2. T4.2 半音音高行与 3 八度音域。
3. T4.3 旋律与和声拆分为对齐的独立窗口。
4. T4.4 FL Studio 风格钢琴卷帘输入。
5. T4.5 回归测试与浏览器验证。

原因：音色是独立的播放层改动，先做不影响布局；半音音域是卷帘和窗口拆分的基础；窗口拆分定下结构后，再统一打磨卷帘输入交互；测试最后统一补齐。

## 6. 风险与注意点

- 采样加载是异步且依赖网络，必须有离线回退，不能让首屏或播放在加载失败时报错。
- 采样资源体积较大，注意不要阻塞首屏，加载状态要可见。
- 3 八度 36 行会显著增高卷帘，需用纵向滚动而不是撑高整页。
- 两个窗口横向联动要避免滚动事件互相触发导致抖动。
- 半音行扩展后，note grid row、拖动吸附、播放头对齐都要同步更新，不能只改视觉。
- 黑白键视觉不能破坏已有长旋律横向滚动与播放头对齐。
