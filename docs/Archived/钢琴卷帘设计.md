请根据当前项目代码，对和声辅助网站的编辑器页面进行一次布局重构。目标是让钢琴卷帘成为页面核心工作区，同时保留底部和声结果抽屉，整体体验更接近 DAW / MIDI editor，而不是普通后台页面。

当前问题：

1. 顶部导航、标题区、工具栏占用过多纵向空间，导致钢琴卷帘区域偏小。
2. 钢琴卷帘是核心编辑区域，但目前视觉上像嵌入式组件，不够主导。
3. 和声结果已经放到底部抽屉，这是正确方向，但现在抽屉边框过硬，像调试区域。
4. 播放控制条目前悬浮在旋律区和和声区之间，容易造成视觉拥挤。
5. 当前卷帘只有 4 小节，适合作为默认可见区域，但不适合作为产品上限。

请按以下方向调整：

一、整体页面结构

将页面整理为四个主要区域：

1. Top App Bar，高度约 48px
   包含品牌、项目入口、语言切换、设置、生成按钮等。
   账号邮箱不要长期占据太多空间，可以收进账户菜单或做截断处理。
2. Editor Toolbar，高度约 48px
   合并当前的“时间线 / 从旋律开始 / 工具按钮”等信息。
   不要让标题和工具栏分成多行占用高度。
3. Melody Piano Roll 主编辑区
   占据页面主要高度。
   这是用户输入、查看、编辑旋律的核心区域。
4. Harmony Drawer 底部抽屉
   用于显示生成后的和声轨道，包括 Bass / Lower / Middle / Upper / Chord。
   抽屉支持收起、预览、展开三种状态。

页面整体建议使用固定高度布局：

```css
body {
  overflow: hidden;
}
```

不要让整个页面滚动，只允许钢琴卷帘内部、和声抽屉内部在必要时滚动。

二、顶部工具栏调整

将当前分散的标题和操作按钮压缩成一条 Editor Toolbar。

例如：

```text
Current phrase · 8 bars · C major    [MIDI | 手动] [时值: 四分] [删除] [撤销] [清空] [更多]
```

中文也可以是：

```text
当前乐句 · 8 小节 · C Major    [MIDI | 手动] [时值: 四分] [删除] [撤销] [清空] [更多]
```

要求：

1. “MIDI / 手动”使用 segmented control，而不是两个普通按钮。
2. “时值”使用 compact select。
3. 删除、撤销、清空、更多保持紧凑。
4. 当前草稿标题不要单独占一整块区域。

三、钢琴卷帘区域

钢琴卷帘应该占据主要空间，建议高度为：

```css
calc(100vh - topBarHeight - toolbarHeight - harmonyDrawerHeight)
```

小节 ruler 和横向滚动控制应当放在卷帘上侧，并成为卷帘的一部分，而不是独立大区域。

推荐结构：

```text
┌──────────────────────────────────────────────┐
│ Bar 1      Bar 2      Bar 3      Bar 4        │
│ ━━━━━━━ draggable viewport / horizontal scroll │
├──────────────────────────────────────────────┤
│                                              │
│              Melody Piano Roll               │
│                                              │
└──────────────────────────────────────────────┘
```

不要使用浏览器默认横向滚动条作为主要视觉。建议设计成 mini timeline navigator，用于表示当前视口位置。

四、小节数量与视口

不要把项目限制为 4 小节。

请改成：

1. 默认项目长度：8 小节。
2. 默认可见区域：4 小节。
3. 用户可以通过顶部横向滚动条查看第 5–8 小节。
4. 后续可扩展支持 16 / 32 / 自定义小节。
5. 可以在工具栏中加入一个轻量的“乐句长度：8 小节”选择器。

建议逻辑：

```text
4 小节 = 快速 demo / 当前视口
8 小节 = 默认创作长度
16 小节 = 完整段落
32 小节 = 高级编辑
```

现在先实现 8 小节项目 + 4 小节视口即可。

五、横向滚动同步

旋律卷帘和底部和声轨道必须横向同步。

当用户在旋律卷帘滚动到第 5 小节时，底部和声轨道也必须同步到第 5 小节。

要求：

1. Melody Piano Roll 与 Harmony Tracks 共用同一个 horizontal scroll state。
2. 顶部 mini timeline 控制的是两者的共同视口。
3. 避免旋律区和和声区显示不同时间位置，防止用户混乱。

六、底部 Harmony Drawer

保留底部和声抽屉，但改成三种状态：

1. Collapsed 收起态
   高度约 40px，只显示一条 Harmony Bar。

```text
和声轨道    生成后会显示 Bass / Lower / Middle / Upper / Chord    [展开]
```

2. Preview 预览态
   生成和声后自动展开，占屏幕高度约 24%–30%。
   显示 Bass / Lower / Middle / Upper / Chord 五条轨道。
3. Expanded 展开态
   用户点击展开或拖动后，旋律区和和声区上下分屏。
   比例可以接近 50% / 50%，用于编辑和声结果。

七、Harmony Drawer 视觉

当前白色描边太硬，请去掉明显白色大边框，改成更正式的暗色玻璃面板。

建议样式方向：

```css
background: rgba(14, 11, 8, 0.92);
backdrop-filter: blur(16px);
border-top: 1px solid rgba(232, 221, 199, 0.16);
box-shadow: 0 -12px 40px rgba(0, 0, 0, 0.35);
```

抽屉顶部可以增加一个小把手：

```text
━━━━
```

用于提示这是可拖拽面板。

八、播放控制条

当前播放控制条悬浮在旋律区和和声抽屉之间，有遮挡和拥挤感。

请优先考虑将播放控制条放入 Harmony Drawer 的 header 区域，或者固定在页面底部。

推荐结构：

```text
Harmony Tracks        [从头播放] [当前小节] [播放] [旋律] [和声]    0.0 拍
Bass
Lower
Middle
Upper
Chord
```

如果保留悬浮样式，也要确保：

1. 不遮挡音符。
2. piano roll 底部有足够 padding。
3. 不压在旋律区与和声区的分界线上。

九、命名与信息层级

请将上方区域命名为：

```text
Melody Editor / 旋律编辑器
```

底部区域命名为：

```text
Harmony Tracks / 和声轨道
```

不要把两个区域都称为钢琴卷帘。
用户应当明确理解：

```text
上方：我输入的旋律
下方：系统生成的和声
```

十、滚动条视觉

右侧纵向滚动条不要使用刺眼的白色默认样式。
建议改为暗色主题下的细滚动条：

```css
width: 6px;
thumb: rgba(255, 255, 255, 0.25);
thumb-hover: rgba(255, 255, 255, 0.45);
track: transparent;
```

滚动条应该属于 piano roll 内部，而不是整个页面。

最终目标：

页面应该像一个精致、专业、沉浸式的音乐创作工具：

```text
顶部：轻量导航
中间：旋律编辑主画布
底部：可收起 / 可预览 / 可展开的和声轨道
```

优先实现：

1. 顶部区域压缩。
2. 默认 8 小节项目 + 4 小节可见视口。
3. 横向滚动放在卷帘上侧。
4. 旋律区与和声区横向同步。
5. 底部和声抽屉三态。
6. 去掉白色硬边框，改成暗色玻璃质感。
7. 播放控制条不再压在两块区域交界处。
