# 第八轮任务总控

> 状态：进行中（A0 已完成；A1–A7 待实施）。
> 依据：[架构审计](01-architecture-audit.md)、[算法审计](02-algorithm-audit.md)、[UI/UX 审计](03-ui-ux-audit.md)。
> 本文件只管理跨域顺序和发布门槛；每个领域的可执行任务见对应专项任务书。

## 1. 交付目标

将当前单体式、外部依赖脆弱的和声工具升级为可长期运营的专业工作台：

- 无 Supabase 时仍可本地创作、保存、试听、生成和导出；上线后通过自有 API 安全同步。
- 默认音色可零网络首播，高质量采样作为可缓存的渐进增强。
- 生成结果具备可声明的乐句和结尾意图；风格由连续光谱控制，搜索、试听和导出共用同一配声结果。
- 工作台保留“旋律编辑 → 和声审阅/编辑”两阶段；第二阶段以 Chord Track 为主，底部抽屉仅显示和弦名称。

## 4. 共同工程规则

1. **先契约、后接线。** 涉及项目、版本、生成方案、配声、同步和音频状态的类型/接口须先审阅并纳入契约测试。
2. **本地模式永不降级为死页面。** 网络、认证、采样或 API 失败时，核心创作路径必须可继续，且状态对用户可见。
3. **每项任务都可验证。** 每个任务在合入前给出自动化测试、手工检查清单或可复现演练证据；不能仅以截图或“能运行”结案。
4. **不迁移测试数据。** 旧 Supabase 测试数据不进入新架构；新库以新的版本化数据模型初始化。
5. **共享领域对象只能有一个真相。** `Project`、`Revision`、`HarmonyPlan`、`Voicing` 等对象不得在 API、算法、UI 中各自复制并漂移。
6. **破坏性决策须留痕。** 改变已锁定边界（例如部署模型、认证提供方、终止语义）前，在本文件记录动因、替代方案和受影响任务。

## 5. 发布门槛（R8）

只有同时满足以下条件才可将第八轮标记为完成：

- A0–A5 的架构专项验收全部通过，且有一次可验证的数据恢复与回滚演练。
- 本地离线模式可创建多个项目、编辑、生成、试听、导出；网络恢复后同步不静默覆盖。
- 默认音色首次播放不依赖网络；采样失败不会阻塞试听；关键性能指标有数据来源。
- 算法回归集覆盖调式、节拍、末音、乐句意图、连续风格和人工编辑；“完整终止”样例均满足其终止约束。
- 搜索评分、可视配声、试听与 MIDI 导出在同一候选上音高一致。
- 阶段 1 与阶段 2 的桌面、移动端关键流程通过验收；阶段 2 不显示默认声部音高，Chord Track 是唯一主画布。
- CI、错误监控、发布版本标记、环境隔离、密钥管理和上线回滚说明已存在且可实际使用。

## 6. 变更控制

- 新发现的问题先关联现有审计编号；没有对应编号时，补充审计再建任务。
- P0 阻塞（数据丢失、无法创作、终止错误、评分/试听/导出不一致）可以暂停下游工作，但必须记录影响范围。
- 视觉偏好类变更不改变 A0–A5 完成定义；不得以视觉重构为理由延后数据可靠性与音频首播问题。
- 专项完成后更新其任务状态、验收证据和遗留风险，并在本文件更新里程碑状态。
