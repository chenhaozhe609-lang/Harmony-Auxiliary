# 第八轮算法审计：乐句、终止与连续风格控制

> 状态：已审计，尚未实施。
> 审计日期：2026-07-12
> 范围：仅覆盖和声生成、乐句/终止、风格控制、配声一致性与相应测试；不覆盖本轮的界面与部署问题。
>
> **执行依赖：** 本文件的实现工作排在 [01-architecture-audit.md](01-architecture-audit.md) 的 A0–A5 之后。算法结论仍有效，但不应抢在新的项目、版本、同步和音频资源边界稳定前实施。

## 1. 审计目的

本文件是后续任务细分与实现的事实基线，避免依据印象重写算法。它记录已由当前代码和测试复现的缺陷、风险和必须保持的约束；它**不是**实现任务清单，也不意味着其中的具体算法方案已经最终定稿。

产品已从简单即用的辅助工具转向专业化和声生成工具。因此本轮目标不应是“让每一段各自选到可用和弦”，而应是让结果形成可解释、可试听、可编辑的完整音乐句法。

## 2. 当前生成链路

```mermaid
flowchart LR
  A[旋律 NoteEvent] --> B[按节奏模式切分 HarmonySegment]
  B --> C[固定和弦词库]
  C --> D[逐段旋律适配分]
  D --> E[Viterbi 全序列选和弦]
  E --> F[后处理：低音转位]
  F --> G[界面显示 / 音频试听 / MIDI 导出]
```

当前实现已经优于早期逐段贪心：`generateCandidates.ts` 以 Viterbi 搜索整条和弦路径，转移分中包含功能进行与简化声部进行，末尾也有软性的终止偏好。

但上述链路中不存在“乐句”这一领域对象：切分出的 `HarmonySegment` 只是和弦时值单位，而不是乐句、乐句末尾或终止意图。Viterbi 因而优化的是一条没有结构标注的线性序列。

## 3. 已验证证据

### 3.1 自动化回归

执行：

```powershell
& $node node_modules\vitest\vitest.mjs run src\music\harmony --reporter=verbose
```

结果：4 个测试文件、24 个测试全部通过。

这只能证明既有断言成立，不能证明长旋律、不同节奏模式及三种风格都能形成完整乐句。现有终止测试主要覆盖一个四段、末音为主音的理想化例子。

### 3.2 长旋律实测

以 `longDemoMelody`（C 大调、4/4）在当前引擎中直接生成，发现下列反例：

| 节奏模式 | 风格 | 实际结尾 | 结论 |
| --- | --- | --- | --- |
| `auto-phrase` | Stable Classical | `… V7 – vi – vi – iii` | 未收束到主功能 |
| `auto-phrase` | Color / Tension | `… V7 – vii° – vi7 – iii7` | 属功能未解决，末尾不稳定 |
| `cadence-aware` | Stable Classical | `… V7 – vi – iii` | “终止感知”模式仍没有完整终止 |
| `cadence-aware` | Color / Tension | `… vii° – vi7 – iii7` | 末尾没有回归主功能 |
| `every-beat` | Color / Tension | `… V7 – iii7` | 直接以未解决的属功能结束 |

这些结果直接复现了“和声之间不够连贯、没有结尾收束、不能形成完整乐句”的反馈。

## 4. 问题清单与根因

| ID | 严重度 | 已确认问题 | 根因 | 用户影响 |
| --- | --- | --- | --- | --- |
| ALG-01 | P0 | 没有乐句模型 | `segmentMelody.ts` 仅决定和弦边界；`auto-phrase` 依据停顿、长音与强拍加边界，但不产出乐句层级、乐句角色或终止意图 | 长旋律被当作单一序列；中间句与结尾句都无法被区别对待 |
| ALG-02 | P0 | 终止只是弱偏好，不能保证收束 | `cadenceEmission` 仅对最后 3 个**和声段**加分/扣分；它不理解小节、时值、乐句边界或终止类型 | 旋律适配分可压过终止偏好；Pop 与 Color 的终止权重更低，尤易悬而不决 |
| ALG-03 | P0 | `cadence-aware` 名称与实际能力不符 | 该模式只在最后一小节插入一个额外切分点，不创建终止约束或验证属到主的解决 | 用户选择“终止感知”后仍得到未收束结果，破坏信任 |
| ALG-04 | P0 | 搜索、显示和试听使用的配声并不统一 | Viterbi 用简化固定声部估分；`applyBassInversions` 在选和弦后再贪心转位；音频与显示各自重建音高 | 声部进行的评分不等于实际听到/看到的结果，且根音位和转位的低音处理不一致 |
| ALG-05 | P1 | 手动替换会破坏上下文 | `getChordAlternatives` 只按当前片段的旋律适配排序，不重算前后转移、声部或终止 | 用户编辑一个和弦即可破坏连贯性、解决或终止 |
| ALG-06 | P1 | 候选总分不反映真实优化目标 | `HarmonyCandidate.score` 只累计基础旋律适配分，遗漏终止、功能转移、色彩惩罚、循环偏好与声部进行 | 分数无法用于解释候选质量，也无法作为专业工具的可靠比较依据 |
| ALG-07 | P1 | 风格是三档硬切换 | 三个 `StyleProfile` 同时切换权重、词库、转位开关等离散属性 | 临界处听感突变，用户无法细致地控制古典功能与现代色彩之间的距离 |
| ALG-08 | P2 | 节拍/复拍子理解不足 | 分段和强拍计算主要使用拍号分子；拍号分母与复拍子分组没有进入乐句/重音模型 | 3/4、6/8 等作品的和声落点可能不符合实际重音与终止位置 |
| ALG-09 | P2 | 回归集覆盖面不足 | 测试验证了算法部件和少量理想路径，但没有跨风格、节奏模式、调式和终止结果的质量门槛 | 改权重或扩词库时容易回归，且难以证明质量改善 |

## 5. 新增产品要求：连续风格控制

用户不接受三个离散档位。风格必须以滑动条连续控制，而不是把三个预设视觉化为三个刻度。

### 5.1 语义要求

建议产品语义为一条 `0–100` 的“功能性 ←→ 色彩/张力”光谱：

| 区间 | 目标听感 | 算法倾向 |
| --- | --- | --- |
| 0 | 功能和声优先 | 清晰功能链、强终止、克制的离调与转位 |
| 50 | 流行写作与平滑低音 | 适度循环功能、较平滑的低音、有限的副属与借用 |
| 100 | 色彩与张力优先 | 更自由的扩展和弦、借用和弦、副属与转位，但悬置必须解决 |

### 5.2 实现约束

- 不能仅把现有三个 `StyleProfile` 放在滑动条的 0、50、100 位置；否则中间仍会发生词库或开关的突变。
- 终止质量是独立于风格的底线。高色彩值可以改变终止的色彩和路径，不能让“完整乐句”变成未解决的结束。
- 连续映射需要覆盖：功能进行权重、终止强度、声部进行权重、色彩预算、扩展词汇可用性/采样、转位偏好与候选多样性。
- 滑动条需要与“乐句意图”分离：同一风格值下，用户仍可选择完整结束、继续句、半终止或循环结尾。

## 6. 后续任务细分必须遵守的架构边界

以下是后续计划必须先解决的边界，不应以“简单调权重”替代。

1. **先建立评估基线。** 构建带乐句边界和预期终止意图的旋律语料；至少覆盖大小调、Dorian、Mixolydian、2/4、3/4、4/4、6/8、不同末音及不同旋律密度。
2. **引入乐句计划层。** 生成前推断并允许用户修正乐句边界，标注每个边界为延续、开放、半终止、完整终止或循环。
3. **在搜索中处理终止。** 用受约束的全局搜索或等价机制，将终止模板、解决规则与旋律末音相容性纳入搜索；不能事后强塞一个 I，也不能只依赖最后三个段的奖励。
4. **统一配声表示。** 搜索状态应最终包含可播放的和弦与声部/低音安排；评分、钢琴卷帘、试听与 MIDI 导出必须消费同一套 `Voicing` 数据。
5. **支持上下文编辑与多样候选。** 替换和弦后应在局部窗口重新优化；候选应是可比较的 n-best 路径，而不是仅三套离散权重的唯一解。
6. **让分数可解释。** 候选总分和界面解释需要反映实际优化项，并提供旋律适配、功能、终止、声部进行和色彩的可读分解。

## 7. 验收口径（供后续任务文档引用）

- 对声明为“完整乐句”的输入，所有主候选必须满足已声明或推断的终止类型；结果不得以未解决属功能或不稳定替代结束。
- 对声明为“循环/继续”的输入，系统不得机械地强制落主；必须明确展示其非终止意图。
- 风格滑动条在相邻取值间不应出现无解释的大幅词汇跳变；极端值应有可感知差异，但完整终止仍受保护。
- 同一候选的搜索评分、可视声部、试听和导出音高必须一致。
- 手动替换后，系统必须重新评估其邻接进行与所在乐句的终止条件。
- 自动化回归需要覆盖所有节奏模式、主要调式、各类句末旋律音、连续风格区间及手动编辑后的局部再优化。

## 8. 审计结论

当前问题不是“Viterbi 不够好”或“几个权重不够大”，而是领域模型缺少乐句和终止意图，且配声没有作为统一优化对象。第八轮算法工作应被视为一次生成模型重构：从“线性和弦标签序列”升级为“具备乐句规划、连续风格控制与一致配声输出的和声方案”。

在上述评估基线、领域模型和验收口径明确前，不应直接调整现有终止权重、追加和弦词库或把三档风格简单改成滑动条。
