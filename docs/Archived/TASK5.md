# Task 5: 用户使用流程重构（登录与引导式创作流程）

## 1. 背景

Task 1–4（里程碑 M1–M6）已经把 Harmony Auxiliary 做成一个可用的本地优先和声工具：落地页、工作台、手动/MIDI 输入、确定性和声引擎、采样播放、MIDI 导出、IndexedDB 单一自动存档槽、中英双语。

但当前产品有两个体验短板：

- **没有用户身份**。所有数据只活在当前浏览器里，单一自动存档槽（`active`）只能保存"最近一次"草稿，换设备、清缓存即丢失，无法管理多个作品。
- **流程是"一屏全暴露"**。命令栏、输入、设置、生成、播放、检查器、导出同时铺在工作台里，老用户高效，但新用户面对一整面墙没有清晰的"下一步"，上手门槛偏高。

Task 5 不改和声算法本身（那是 Task 7），也不重做视觉系统（那是 Task 6）。Task 5 的目标是**重构用户使用流程**：引入第三方认证（Supabase）带来真实账户与登录后的云端项目管理，并把核心创作链路重组为一条清晰的引导式分步流程。

> **版本约束变更**：PRD 中的 local-first / 无账户 / 无后端等"强制约束"属于上一版本（MVP）。进入本版本后，这些约束**自动降级为可忽略**。本轮以"登录 + 云端"为主路径，不再为"无后端也要完整可用"做妥协设计。仍保留的"无密钥可构建可测试"只是工程层面的 CI 便利，不再是产品级承诺。

## 2. 产品目标

1. 接入 **Supabase** 作为第三方认证 + 数据库服务，支持账密 / 邮箱登录与会话持久化。
2. 登录用户可在云端**保存、命名、打开、重命名、删除多个和声项目**，跨设备可见。
3. 把"输入 → 设置 → 生成 → 试听 → 选择 → 导出"重组为一条**引导式分步流程**，降低新用户上手门槛，同时为老用户保留直达完整工作台的快捷路径。
4. 登录作为**软门槛**：落地页弹出可关闭的登录提示；**进入工作台必须登录**；未登录用户可通过 "ask for a demo" 进入 **mock 演示版**体验核心流程，但不能云端保存。
5. 明确**账户与隐私的衔接**：哪些数据上云、何时上云、演示版能做什么、隐私文案如何更新。

## 3. 非目标

本轮暂不做以下内容：

- 和声生成算法 / 评分逻辑的改动（Task 7）。
- 视觉系统重设计、组件库重构、动效体系（Task 6）。
- 第三方社交登录（Google / GitHub OAuth）—— 本轮先做邮箱 + 密码；OAuth 留接口但不实现 UI。
- 协作编辑、项目分享链接、teacher review、社区预设（PRD V3 之后）。
- 把原始 MIDI 二进制文件上云（隐私考虑，沿用"原始 MIDI 默认留本地"原则）。
- 付费 / 订阅 / 用量计费。
- 服务端和声计算（引擎仍在客户端运行）。

## 4. 关键设计约束

### 4.1 认证门槛模型（软门槛 + 演示版）

local-first 不再是强约束，登录是新版本的主路径。门槛分三层：

- **落地页（未登录）**：进入后弹出可关闭的登录 / 注册提示。关闭后可继续浏览落地页内容，并能点击 "ask for a demo" 进入演示版。
- **工作台（需登录）**：点击"进入工作台 / 开始创作"等主 CTA 时，未登录则拦截并要求登录 / 注册；登录成功后进入完整工作台，项目默认走云端。
- **演示版（mock，无需登录）**：通过 "ask for a demo" 进入一个预置示例旋律的沙盒工作台，可输入、生成、试听、导出，但**禁用云端保存**，并持续提示"登录以保存作品"。演示数据仅留在本地（沿用现有 IndexedDB），不算正式账户数据。

工程与安全约束：

- Supabase 通过 `VITE_SUPABASE_URL` 与 `VITE_SUPABASE_ANON_KEY` 配置。
- **未配置密钥时**：为不阻塞本地开发 / CI，认证降级为"未配置"态——主 CTA 可临时直通演示版或工作台（开发开关），`tsc -b` / `vitest` / `vite build` 无密钥必须通过。这是 CI 便利，不是产品承诺。
- 密钥仅使用 `anon` public key（前端可暴露），访问控制靠 Supabase **行级安全（RLS）**；service-role key 永不进前端 / 仓库。

### 4.2 隐私模型

- 云端只存储**项目快照 JSON**（旋律音符 + 设置 + 和声候选 + 选择状态，即现有 `StoredProjectSnapshot`），**不含原始 MIDI 文件二进制**。
- **演示版**数据只留本地（IndexedDB），永不上云。
- 登录用户的项目**默认走云端**；本地 IndexedDB 退化为离线缓存 / 演示沙盒，不再是主存储。
- 隐私文案需更新：说明登录后旋律与和声数据存到 Supabase，演示版纯本地。
- "清除数据"区分范围：演示 / 本地缓存，与云端项目（云端删除需二次确认）。

### 4.3 数据模型对齐

- 复用现有 `StoredProjectSnapshot`（[src/music/types.ts](../src/music/types.ts)）作为云端 `projects.snapshot` 的 JSONB 负载，避免重复定义。
- Supabase `projects` 表结构（建议）：
  - `id uuid primary key default gen_random_uuid()`
  - `user_id uuid not null references auth.users(id) on delete cascade`
  - `title text not null`
  - `snapshot jsonb not null`（= `StoredProjectSnapshot`）
  - `created_at timestamptz not null default now()`
  - `updated_at timestamptz not null default now()`
  - RLS 策略：`user_id = auth.uid()` 才可 select / insert / update / delete。
- 建库 SQL / RLS 策略以迁移脚本形式落在 `supabase/`（或 `docs/`）目录，便于复现。

## 5. 任务拆分

### T5.1 Supabase 接入与环境配置

目标：在不破坏 local-first 的前提下接入 Supabase 客户端。

任务：

- 添加依赖 `@supabase/supabase-js`。
- 新增 `src/services/supabaseClient.ts`：从 `import.meta.env` 读取 URL / anon key，**缺失时导出 `null` 并暴露 `isSupabaseConfigured` 布尔**，不抛错。
- 新增 `.env.example`，写明 `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY`；确认 `.env*` 已被 `.gitignore` 忽略。
- 提供建表 + RLS 的 SQL 迁移文件（含 `projects` 表、`updated_at` 触发器、RLS 策略）。
- README 增补"可选：配置 Supabase 启用账户"小节。

验收标准：

- 不配置任何密钥时，`tsc -b` / `vitest` / `vite build` 全通过，应用以本地模式运行无报错。
- 配置密钥后，客户端可成功初始化（控制台无错误）。

### T5.2 认证 UI 与会话管理

目标：用户可注册、登录、登出，会话刷新后保持。

任务：

- 新增 `src/app/auth/` 模块：`AuthProvider`（React Context）封装 session、user、`signUp / signInWithPassword / signOut`，订阅 `onAuthStateChange`。
- **落地页登录提示**：进入落地页弹出可关闭的登录 / 注册面板（邮箱 + 密码，注册 / 登录切换，邮箱验证提示）。关闭后保留入口。
- **工作台软门槛**：未登录点击主 CTA（进入工作台 / 开始创作）→ 拦截并唤起登录面板；登录成功后进入工作台。
- **演示版入口**："ask for a demo" 按钮无需登录，直接进入 mock 沙盒（见 T5.4）。
- 已登录时命令栏显示用户邮箱与"登出"。
- 错误与状态走现有 message-banner 体系（沿用 `tone: error | status`），并接入 i18n。
- 会话由 Supabase SDK 自动持久化（localStorage），刷新页面保持登录态。
- 未配置 Supabase 时认证降级为"未配置"态（开发开关直通，不报错）。

验收标准：

- 可用邮箱 + 密码注册并登录；刷新后仍登录。
- 未登录点击进入工作台被拦截并要求登录；登录后可进入。
- 未登录可经 "ask for a demo" 进入演示版，且演示版不能云端保存。
- 认证失败（密码错、邮箱已注册等）有清晰的本地化提示。

### T5.3 云端项目管理

目标：登录用户可管理多个云端和声项目。

任务：

- 新增 `src/services/projectsRepository.ts`：`listProjects / createProject / updateProject / renameProject / deleteProject`，负载使用 `StoredProjectSnapshot`，全部经 RLS。
- 工作台新增"项目"区域 / 抽屉：列出当前用户项目（标题 + 更新时间），支持打开、重命名、删除（删除二次确认）。
- "保存到云端"动作：把当前 `AppState` 经 `createProjectSnapshot` 序列化后 upsert；区分"新建项目"与"更新当前项目"。
- 打开云端项目 → 复用现有 `restore-snapshot` reducer 流程载入工作台。
- 首次登录且本地存在演示 / 草稿存档时，提示"将本地内容另存为云端项目"（一次性迁移，不自动覆盖）。
- 云端写入失败（离线 / 网络错）有提示且不影响本地编辑。

验收标准：

- 登录用户可保存 ≥2 个项目并在列表中切换打开，内容正确还原。
- 重命名、删除生效且持久（刷新后一致）。
- 在另一浏览器 / 设备登录同账户可见同样的项目列表。
- 演示版中云端保存动作禁用并提示登录；登录后可一键把演示内容存为项目。

### T5.4 引导式分步创作流程

目标：把核心链路重组为清晰的分步引导，降低上手门槛。

任务：

- 设计一条引导流程，覆盖：**① 选择输入（导入 MIDI / 手动 / 示例）→ ② 确认设置（调性、拍速、和声密度、音色）→ ③ 生成 → ④ 试听与对比候选 → ⑤ 选择并微调和弦 → ⑥ 导出 / 保存**。
- 以"步骤指示 + 当前步骤主操作 + 上一步/下一步"的形式承载，弱化一次性铺满的控件墙。
- 步骤状态与现有 `AppState`/`harmonyStatus` 派生（如无旋律禁用生成、无候选禁用导出），不引入与 reducer 冲突的第二真相源。
- 为老用户保留"展开完整工作台 / 跳过引导"的逃生通道；记住用户偏好（引导 vs 专家视图）到本地偏好。
- **登录工作台与演示版共用同一套引导流程**；演示版在"保存 / 导出到云端"步骤替换为"登录以保存"的提示，其余步骤一致。
- 引导流程在移动端（360px）依然不溢出、可用。
- 全程接入 i18n（中 / 英）。

验收标准：

- 新用户能沿引导逐步从空白走到导出，每步有清晰"下一步"。
- 任一步的禁用 / 可用状态与真实数据一致（无旋律不能生成、无候选不能导出）。
- 老用户可一键切到完整工作台，且偏好被记住。
- 引导与专家视图共享同一份状态，切换不丢数据。
- 演示版引导可走完到导出，但云端保存步骤替换为登录提示。

### T5.5 账户与隐私衔接

目标：让"本地 vs 云端""游客 vs 登录"的边界对用户透明。

任务：

- 更新隐私 / 数据说明文案：演示版纯本地、登录后云端保存什么、原始 MIDI 不上云。
- "清除数据"区分范围：演示 / 本地缓存 vs 云端项目（云端删除二次确认）。
- 落地页登录提示与 "ask for a demo" 入口文案清晰：说明登录能跨设备保存、演示版不保存。
- 演示版中尝试云端动作时给出友好的"登录后可用"引导，而非静默失败。

验收标准：

- 用户能从 UI 清楚知道数据存在哪（演示本地 / 登录云端）、登录会同步什么。
- 清除数据的本地 / 云端范围可控且有确认。
- 落地页登录提示可关闭，关闭后仍可通过演示版体验，不被死锁。

### T5.6 i18n、回归测试与浏览器验证

目标：避免认证、项目管理与引导流程引入回归。

任务：

- 所有新增文案进入 [src/app/i18n.ts](../src/app/i18n.ts) 的中 / 英表，无硬编码裸串。
- 为 `projectsRepository` 序列化 / 反序列化（snapshot ↔ 表负载）加单元测试（可 mock Supabase 客户端，不依赖真实网络）。
- 为 `supabaseClient` 的"未配置降级为 null"加单元测试。
- 为引导流程的步骤可用性派生逻辑（能否生成 / 导出）加单元测试。
- 浏览器验证脚本（沿用 `scripts/verify-*.mjs` 风格）覆盖：游客本地流程不受影响、引导流程逐步推进、（如本地可连 Supabase）登录与保存项目、移动端无横向溢出。
- 保留 Task 2/3/4 已有验证脚本。

验收标准：

- `tsc -b` 通过。
- `vitest run --passWithNoTests` 通过（含新测试，且无密钥也能跑）。
- `vite build` 通过。
- 浏览器验证覆盖：游客流程、引导分步、（可选）登录+云端保存、无横向溢出。

## 6. 建议实施顺序

1. **T5.1** Supabase 接入与环境配置（打好可降级的地基）。
2. **T5.2** 认证 UI 与会话管理（先有登录态）。
3. **T5.3** 云端项目管理（登录态之上的数据能力）。
4. **T5.4** 引导式分步创作流程（重组前端使用链路）。
5. **T5.5** 账户与隐私衔接（把以上能力的边界说清楚）。
6. **T5.6** i18n、回归测试与浏览器验证（统一补齐）。

原因：认证是其余一切的前置；项目管理依赖登录态；引导流程是独立的前端重组，可在数据能力就绪后专注打磨；隐私衔接需要前述能力都在场才能准确描述；测试最后统一补齐。

## 7. 风险与注意点

- **软门槛不能变死锁**：落地页登录提示必须可关闭，关闭后仍能经 "ask for a demo" 体验；不能出现"不登录就什么都点不动"的死循环。
- **CI 可降级**：无密钥时构建 / 测试必须照常（开发开关直通）；这是工程便利，不是 local-first 承诺。
- **密钥安全**：前端只用 `anon` key，真正的访问控制靠 RLS；service-role key 永不进前端 / 仓库。
- **隐私边界**：演示版纯本地不上云；登录项目默认云端；原始 MIDI 不上云；文案要诚实。
- **状态单一真相源**：引导流程必须从现有 reducer / `AppState` 派生，不能新建会与之冲突的并行状态机。
- **快照兼容**：云端复用 `StoredProjectSnapshot`，注意 `schemaVersion`，为将来迁移留出空间。
- **离线与失败**：网络写入失败要降级提示，不能丢掉用户正在编辑的本地内容。
- **移动端**：认证面板、项目列表、引导步骤在 360px 宽度下不能溢出或重叠。
- **范围克制**：本轮不碰算法（Task 7）与视觉重设计（Task 6），避免三件事缠在一起难以验收。
